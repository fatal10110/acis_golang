# acis_golang

A Go port of the aCis Lineage II server for the Interlude client
(protocol revision 746). It has a login server and a game server. Both use the same MariaDB schema,
config files, datapack and geodata as the aCis Java server, so an existing installation can switch
over.

## Features

- **Two processes**, like the reference server: a login server (accounts, server list, session
  keys, IP bans) and a game server, joined by the GS-LS link protocol.
- **Broad game coverage**: world and visibility, geodata and pathfinding, combat, skills and
  effects, items, inventory, trade and stores, pets and summons, parties, clans, castles, sieges,
  clan halls, Seven Signs, Olympiad, quests and scripted NPCs, boats, fishing, admin commands, and
  more.
- **Same data on disk**: datapack XML and HTML stay files; the database schema is the aCis schema.
- **Concurrency without lock soup**: each actor runs its work on its own FIFO queue over a shared
  worker pool, and database writes go through ordered persistence lanes.
- **Operations**: Docker Compose stack, systemd drop-in, structured logs, `pprof` and `expvar`
  endpoints, IP ban and item APIs, graceful shutdown that saves every player.
- **Tested end to end**: behavior suites drive the server over the real client protocol against a
  real MariaDB, and the inbound framing, decryption and packet decoders are fuzzed.

## Quick start

You need Docker with Compose v2 and a full `aCis_datapack` checkout (with geodata) next to this
repository. The in-repo `aCis_datapack/` is a test copy without geodata; do not run servers from it.

```bash
cat > .env <<'END'
ACIS_DATAPACK_DIR=../aCis_datapack
ACIS_DB_ROOT_PASSWORD=change-me
ACIS_PUBLIC_HOST=127.0.0.1
END
```

```bash
docker compose --profile servers build
```

```bash
docker compose --profile servers up -d
```

The first start loads the schema, writes `./config` and registers game server 1. Point an
Interlude client at `ACIS_PUBLIC_HOST`, port 2106. With `AutoCreateAccounts = True` (the default),
the first login creates the account. [docs/ops/docker.md](docs/ops/docker.md) has the details.

To build and run the binaries without Docker, you need Go (the version in `go.mod`) and MariaDB.
Follow [docs/run-servers.md](docs/run-servers.md).

## Testing

```bash
make test-db-up
```

```bash
make test-race
```

`make test-unit` runs the database-free core. `make test-one PKG=tests/items` runs one
behavior suite. `make fuzz` fuzzes the inbound decoders. Tests are behavior-first: full-flow
scenarios in `tests/<domain>/` drive real packets against a real MariaDB. See
[docs/development.md](docs/development.md#tests) and
[docs/agents/test-strategy.md](docs/agents/test-strategy.md).

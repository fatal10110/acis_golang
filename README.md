# acis_golang

**A Lineage II game server written in Go.**

acis_golang is a Go version of aCis, a Java server for the Lineage II *Interlude* client (protocol
revision 746). It includes a login server and a game server. Both use the same database, config
files and game data as the Java server, so an existing aCis installation can switch to it, and switch
back, without converting anything.

> **Educational project.** All code in this repository was generated by AI, as an experiment in
> porting a large Java codebase to Go. Read the [educational purpose](#educational-purpose-only)
> and the [legal notice](#legal-notice) before you use it.

## Status

The port is a work in progress. Most game systems run, and a production server is deployed from
this repository. Systems that do not run yet are tracked as open issues under the
[milestones](https://github.com/fatal10110/acis_golang/milestones).

## Features

- **Drop-in compatible.** Same client protocol, database schema, config keys, game data files and
  geodata as the aCis Java server.
- **Broad game coverage.** The world, terrain and pathfinding, combat, skills and effects, items and
  trade, pets and summons, parties and clans, castles, sieges and clan halls, Seven Signs, the
  Olympiad, quests and scripted NPCs, boats, fishing, admin commands, and more.
- **Built for many players.** Each character and monster runs its work on its own task queue, and a
  pool of workers runs the queues on every CPU core. Database writes happen in the background, in
  order.
- **Ready to operate.** Docker Compose stack, systemd support, structured logs, metrics and
  profiling endpoints, an IP ban API, and a shutdown that saves every player.
- **Tested like a player plays.** Tests start a real server, connect a scripted client, and check
  the packets, the world and the database. The packet decoders are also fuzzed.

## Quick start

The fastest way to run the servers is Docker. You need:

- Docker with Compose v2;
- a full `aCis_datapack` checkout, including geodata, in the folder next to this repository.

The `aCis_datapack/` folder inside this repository is a smaller copy for tests, without geodata.
Do not run servers from it.

1. Create a `.env` file with your settings:

   ```bash
   cat > .env <<'END'
   ACIS_DATAPACK_DIR=../aCis_datapack
   ACIS_DB_ROOT_PASSWORD=change-me
   ACIS_PUBLIC_HOST=127.0.0.1
   END
   ```

2. Build the server image:

   ```bash
   docker compose --profile servers build
   ```

3. Start the database and both servers:

   ```bash
   docker compose --profile servers up -d
   ```

On the first start, the stack creates the database, writes a `./config` folder and registers game
server 1. Then point an Interlude client at `ACIS_PUBLIC_HOST`, port 2106. With the default
`AutoCreateAccounts = True`, logging in with a new name creates the account.

More detail: [docs/ops/docker.md](docs/ops/docker.md). To run the programs without Docker, see
[docs/run-servers.md](docs/run-servers.md).

## Repository layout

| Folder | Contents |
| --- | --- |
| `cmd/` | the programs: `loginserver`, `gameserver`, and their tools ([docs/tools.md](docs/tools.md)) |
| `internal/loginserver/` | the login server |
| `internal/gameserver/` | the game server: network, world, terrain, characters, skills, items, and one package per game system |
| `internal/link/` | the protocol between the game server and the login server |
| `internal/commons/`, `internal/config/` | code shared by both servers |
| `internal/gameservertest/`, `internal/testsupport/`, `internal/dbtest/` | the test harness |
| `tests/` | behavior tests, one folder per game area |
| `aCis_datapack/` | a copy of the game data for tests, without geodata |
| `ops/` | Docker, systemd and datapack checksum files |
| `docs/` | the documentation |

## Testing

Start the test database once, then run the full test suite with the race detector:

```bash
make test-db-up
```

```bash
make test-race
```

While you work, `make test-unit` runs the fast tests that need no database, and
`make test-one PKG=tests/items` runs one area. See
[docs/development.md](docs/development.md#tests).
